# Разные методы генерации из диффузионных моделей

Учебный исследовательский проект по LLM in CV. Сравниваем, как сэмплер и расположение
уровней шума влияют на качество и скорость генерации при одинаковом числе вызовов
нейросети (NFE). Затем планируем подобрать расписание, которое уменьшает MSE
относительно длинной детерминированной генерации на тех же начальных шумах.

[Краткий отчёт по этапу 1, PDF](output/pdf/rk1_diffusion_sampling_report.pdf).

## Модель, архитектура и методы

Используем готовую безусловную DDPM `google/ddpm-cifar10-32` для RGB-изображений
CIFAR-10 размером 32×32. Веса фиксированы на ревизии
`267b167dc01f0e4e61923ea244e8b988f84deb80`.

Нейросеть — `UNet2DModel`, 35,7 млн параметров. Это энкодер и декодер со skip-связями,
остаточными блоками и блоками self-attention. Четыре уровня имеют 128/256/256/256
каналов, timestep кодируется позиционным embedding. Вход — зашумлённое изображение
`[B, 3, 32, 32]` и timestep, выход — предсказание шума epsilon той же формы.
Сэмплер преобразует это предсказание в следующее состояние изображения.

| Метод | Как делает шаг | Вызовы сети |
|---|---|---|
| DDIM, eta=0 | Детерминированно переносит оценку изображения и шума на следующий уровень | Один на узел |
| DPM-Solver++ 2M | Использует текущую и предыдущую оценки чистого изображения для второго порядка | Один новый на узел |
| Heun в координатах EDM | Пробный Euler-шаг и коррекция по двум наклонам | `2N−1` для N узлов, с Euler-переходом к нулевому шуму |

Реализованы расписания `uniform_t`, `log_sigma` и `karras` с rho=7. Общие сетки
проходят от t=999 до последнего запроса t=0, затем к чистой точке sigma=0.
При бюджете 39 NFE DDIM и DPM++ используют 39 узлов, Heun — 20.
Обвязка переводит epsilon в оценку x₀ и согласует состояния VP-модели с EDM-координатами.
Формулы и проверки описаны в [разборе методов](docs/samplers_math.md).

## Полученные результаты

Измерения выполнены на Tesla T4, float32, batch size 64. FID рассчитан для 5000
сгенерированных изображений относительно CIFAR-10 train из 50 000 изображений.
Время в таблицах — денойзинг с синхронизацией GPU. Загрузка модели, прогрев,
архивирование и расчёт FID выполняются вне этого замера.

**Библиотечный baseline** — DDIM из Diffusers, 100 NFE, eta=0, native leading,
clipping=True. Получены FID **15,6571**, время **1505,17 с** и **0,3010 с/изображение**.
Пик CUDA allocated составил **0,834 GiB**.

**Собственные сэмплеры** — один общий банк из 5000 шумов, `uniform_t`, clipping=False.

| Метод | NFE | FID ↓ | Денойзинг, с | Секунд/изображение |
|---|---:|---:|---:|---:|
| DDIM | 39 | 20,8112 | 548,78 | 0,1098 |
| DPM-Solver++ 2M | 39 | 18,7129 | 558,05 | 0,1116 |
| Heun | 39 | 27,0767 | 558,56 | 0,1117 |

DPM++ 2M получил лучший FID в этом сравнении. На части изображений у него чётче
контуры, у Heun заметнее зернистость. Вывод пока относится к одному банку и
расписанию `uniform_t`. Библиотечный baseline использует другие clipping и начало
траектории, поэтому межметодное ранжирование проводим внутри таблицы при 39 NFE.
Сетки и наблюдения сохранены в [визуальном разборе](docs/study_uniform39_results.md).

В выполненном ноутбуке 04 проверен длинный эталон на 16 шумах. MSE DDIM-500
относительно DDIM-1000 равна **5,23×10⁻⁶**. Ошибки коротких методов при 39 NFE
относительно DDIM-1000 составили **2,20×10⁻³** для DDIM, **3,23×10⁻⁴** для DPM++ 2M
и **9,57×10⁻⁴** для Heun. Эти значения включены в PDF.

В сохранённых Colab-запусках прошли 35 тестов и 5 сверок с Diffusers на настоящей
модели. Максимальная ошибка промежуточного состояния — **5,72×10⁻⁶**.
Полная сетка из 27 FID-конфигураций, подтверждение на новых шумах и поиск опорных
уровней остаются следующими шагами. MSE оценивает близость к численному эталону,
FID — качество распределения изображений.

## Как воспроизвести работу

Основной маршрут с загрузкой ZIP с компьютера — **01 → 03 → 04**.
Ноутбук 02 — отдельный маршрут для pilot и ручного запуска конфигураций, с Google Drive.
Для воспроизведения baseline и первичного сравнения достаточно **01 → 03**.
Ноутбук 04 расширяет исследование расписаний и устойчивости результатов.

|---|---|---|---|
| [01_baseline_colab.ipynb](notebooks/01_baseline_colab.ipynb) | ZIP исходников проекта | Проверяет среду и pilot, генерирует baseline DDIM-100 на 5000 шумах, считает FID | Полный ZIP baseline с FID, NFE, временем, шумами, тензорами и PNG |
| [02_samplers_colab.ipynb](notebooks/02_samplers_colab.ipynb) | ZIP исходников, доступ к Google Drive | Проверяет три реализации, сравнивает pilot при 19 NFE, считает MSE к DDIM-500/1000, готовит конфигурации полного FID | Таблицы и сетки pilot, MSE, JSON-конфигурации. Полные FID-прогоны запускаются вручную по одному |
| [03_sampler_study_from_backup.ipynb](notebooks/03_sampler_study_from_backup.ipynb) | Один полный финальный ZIP baseline из 01 | Восстанавливает baseline и шумы, проверяет реализации, сравнивает три сэмплера при 39 NFE на 5000 изображениях каждый | Три полных ZIP методов и ZIP сравнительного отчёта с JSON/CSV/сетками |

### 1. Подготовить исходники для 01

На компьютере клонируйте рабочую ветку и соберите архив.

```bash
git clone --branch codex/baseline https://github.com/maria-igntv/diffusion-sampling-mipt.git
cd diffusion-sampling-mipt
python3 scripts/build_colab_bundle.py
```

Получится `dist/diffusion-sampling-colab.zip`. Архив содержит код, конфигурации,
ноутбуки и документацию. Веса модели, CIFAR-10 и веса Inception загрузятся при первом
использовании. Для установки зависимостей и первого запуска нужен интернет.

### 2. Выполнить 01 и сохранить baseline

1. Откройте 01 в Colab и выберите T4 GPU.
2. В ячейке загрузки выберите `diffusion-sampling-colab.zip` с компьютера.
   Проект восстановится в `/content/diffusion-sampling`.
3. Оставьте `RUN_TAG='t4_ddim100_baseline_v1'`, `BATCH_SIZE=64`, float32 и 100 NFE.
4. Выполните ячейки по порядку — тесты, банк шумов, pilot, первый батч, оставшуюся
   генерацию, FID и финальный экспорт. Посмотрите preview и заполните `VISUAL_NOTES`.
5. Скачайте полный `t4_ddim100_baseline_v1_full_final_fid_*.zip` и выполненный IPYNB.
   Проверьте, что сгенерировано 5000 изображений, NFE=100, FID конечен и
   `baseline_metrics_complete=True`.

Полный финальный ZIP включает точные шумы и исходники, он используется в 03.
Архив `initial_noises_*.zip` и промежуточные `delta_*.zip` сохраняйте как резервные
копии по ходу генерации. Подробные параметры есть в [инструкции T4](docs/t4_baseline_run.md).

### 3. Выполнить 03 и сравнить методы

1. Откройте 03 в новой T4-сессии. Выберите **один полный финальный ZIP baseline** из 01.
   Ноутбук проверит SHA256 и восстановит исходники, результаты и начальные шумы.
2. Оставьте `NFE_BUDGET=39`, `NUM_IMAGES=5000`, `BATCH_SIZE=64`,
   `BLOCK_BATCHES=16`, `RESTORE_STUDY_BACKUPS=False`.
3. Выполните проверки и pilot, затем блоки генерации и FID для DDIM, DPM++ 2M и Heun.
   После каждого блока сохраняйте checkpoint, скачивание выполняйте отдельной ячейкой.
4. В конце выполните сравнение и экспорт отчёта. Должны быть готовы три запуска
   по 5000 изображений с NFE=39, конечными FID и одинаковым хешем начальных шумов.

Сохраните `ddim_uniform_t_nfe39_full_final_fid_*.zip`,
`dpmpp_2m_uniform_t_nfe39_full_final_fid_*.zip`,
`heun_uniform_t_nfe39_full_final_fid_*.zip` и `study_uniform39_v1_report_*.zip`.
Суффиксы ZIP формируются заново при экспорте. Версии `_reviewed.zip` дополнены
визуальными наблюдениями. `RUN_LONG_REFERENCE=False` оставляет длинный эталон
для отдельного исследования в 04.

### 4. Выполнить расширение в 04

В новой сессии Colab выберите T4. В первом диалоге загрузки **выберите сразу три
финальных ZIP методов из 03**. Для первого запуска оставьте
`STUDY_NAME='extended_study_v1'`, `RESTORE_PROGRESS=False`, `MAX_NEW_BATCHES=16`.
Выполните подготовку, сохраните support ZIP, дождитесь успешных тестов и сверки с Diffusers.

Далее соблюдайте порядок фаз.

| Порядок | Фаза | Вычисления и ожидаемый результат |
|---|---|---|
| 1 | `convergence` | DDIM-500/1000 и три коротких метода на 16 шумах. Ошибка между эталонами и MSE методов |
| 2 | `mse64` | DDIM-1000 и 27 конфигураций на 64 шумах. Таблица MSE, ошибки отдельных изображений и графики |
| 3 | `grid` | 3 метода × 3 расписания × 3 бюджета 19/39/79 NFE, по 5000 изображений. FID, время и NFE |
| 4 | Фиксация выбора | После полного `grid` выбрать лучшее расписание каждого метода при 39 NFE и добавить uniform_t-контроли. Сохранить обновлённый support ZIP |
| 5 | `mse1024` | Длинный эталон и выбранные настройки на 1024 новых шумах. Проверка MSE |
| 6 | `independent` | Выбранные настройки на двух новых банках по 5000 шумов. Повторные FID и их разброс |

В исходных ячейках 04 один `run_next_block` продвигает одну задачу. Отчёт фазы
доступен после `done=True` у всех её задач, фиксация выбора — после полного `grid`.
Сохранённые три прогона из 03 переиспользуются при совпадении окружения и условий.

Для автоматического продолжения после подготовки и проверок добавьте следующую
ячейку вместо ручного выполнения разделов 5–7. Она загружает функцию продолжения
из фиксированной версии репозитория и использует текущие `PROJECT`, `plan` и
`SOURCE_BUNDLE`.

```python
from urllib.request import urlretrieve

helper_url = (
    'https://raw.githubusercontent.com/maria-igntv/diffusion-sampling-mipt/'
    '7e5a22110b8909e33d6499de1c5a01db1562a83b/scripts/continue_extended_study.py'
)
urlretrieve(helper_url, '/content/continue_extended_study.py')
%run -i /content/continue_extended_study.py

result = continue_study(through='independent', max_batches=16, max_minutes=45)
print(result)
```

Готовые задачи пропускаются, отчёты и фиксация выбора выполняются автоматически.
Лимит 45 минут проверяется между блоками. Для непрерывного выполнения задайте
`max_minutes=None`, для остановки после MSE-исследования — `through='mse64'`.
Полное расширение требует нескольких часов GPU. Функция проверена на порядке
фаз, пропуске готовых задач и возобновлении после остановки. Полный GPU-прогон
автоматического продолжения остаётся выполнить.

После остановки скачайте ZIP из `results/exports/extended_study_v1` через панель
файлов Colab или отдельную ячейку скачивания. Сохраняйте последний полный checkpoint
**каждого** запуска, последний support ZIP и последний reports ZIP.

### 5. Как продолжить после остановки

- **Текущая среда Colab сохранилась.** Повторно вызовите функцию продолжения или
  ячейку блока с тем же планом. Уже загруженные архивы и готовые батчи используются дальше.
- **Среда 03 потеряна.** Снова загрузите полный baseline, затем включите
  `RESTORE_STUDY_BACKUPS=True` и выберите последние полные ZIP начатых методов.
- **Среда 04 потеряна.** Сначала восстановите три исходных ZIP из 03. Затем включите
  `RESTORE_PROGRESS=True` и во втором диалоге выберите один последний support ZIP
  вместе с последним полным checkpoint каждого запуска, который хотите восстановить.
  Сохраните прежнее `STUDY_NAME`.

Рабочая папка `/content` существует в пределах сессии. ZIP на компьютере служат
постоянными копиями. Дождитесь завершения скачивания в браузере перед следующим
вычислительным блоком.

## Условия воспроизводимости

- Начальные шумы создаются на CPU с отдельным seed для каждого изображения,
  сохраняются как тензоры и проверяются по SHA256. Основной FID-банк — seeds 50000–54999.
- В 04 debug использует seeds 10000–10015, `mse64` — 30000–30063,
  `mse1024` — 40000–41023, подтверждающие FID — 60000–64999 и 70000–74999.
- При сравнении фиксируются веса, банк шумов, фактический NFE, точность, batch size,
  clipping, края траектории, GPU и версии библиотек. TF32 отключён.
- В `manifest.json` записываются конфигурация, окружение и хеши весов, шумов и кода.
  Продолжение проверяет их совместимость. При изменении окружения используйте новое
  имя исследования и пересчитайте сравниваемую группу в одинаковых условиях.
- FID считается через `torch-fidelity==0.3.0`, `inception-v3-compat`, 2048 признаков,
  по RGB PNG uint8 32×32. Выборка generated-5k сравнивается с CIFAR-10 train-50k.
  Diffusers закреплён на `0.35.2`.
- Точный повтор прежних измерений требует сохранённого кода и окружения из архива.
  Новая установка берёт PyTorch и torchvision из доступного окружения. Между CUDA,
  MPS и CPU возможны численные различия, время сравнивается внутри одного устройства.

| Файл результата | Для чего нужен |
|---|---|
| `manifest.json`, `model_contract.json`, `sampling_plan.json` | Настройки, версии, интерфейс модели и фактическая сетка |
| `batches/*.pt`, `images/*.png`, `preview.png` | Сырые результаты, изображения для FID и сетка для просмотра |
| `summary.json`, `fid.json` | Число изображений, NFE, время и протокол FID |
| `visual_review.md` | Наблюдения о качестве, появляется после заполнения визуального описания |
| Полный checkpoint ZIP | Исходники, точные шумы и состояние отдельного запуска |
| Support ZIP в 04 | План, выбранные настройки и все банки шумов |
| Reports ZIP | Таблицы, графики и сравнения, подготовленные на момент экспорта |

## Проверки и локальный запуск

Для командной строки установите зависимости и запустите проверки.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e . matplotlib
python -m diffusion_sampling doctor
python -m unittest discover -s tests -v
```

Тесты используют маленькие модели и временные данные. Численная сверка на настоящих
весах запускается отдельно.

```bash
python scripts/verify_samplers.py --device cuda
```

На Apple Silicon доступен `--device mps` в CLI. FID выполняется на CPU, измерения
Mac образуют отдельную группу. Подробный план поиска расписания находится
в [плане исследования](docs/research_plan.md).
