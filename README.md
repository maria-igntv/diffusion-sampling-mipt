# Разные методы генерации из диффузионных моделей

Исследуем, как метод сэмплирования и расположение уровней шума влияют на качество
изображений при одинаковом числе вызовов замороженной нейросети.

Модель — `google/ddpm-cifar10-32`, U-Net примерно с 35,7 млн параметров,
безусловная генерация RGB 32×32. Веса не обучаем. Сеть принимает изображение
и timestep и предсказывает шум. Сэмплер вычисляет следующее состояние.

**Сейчас реализован первый этап:** воспроизводимый baseline с DDIM из Diffusers,
фиксированные шумы, счётчик NFE, измерение времени, сохранение сырых результатов,
продолжение прерванного запуска, экспорт PNG и вычисление FID.
Собственные DDIM, DPM-Solver++ и Heun пока не реализованы.
Наличие кода оценки не означает, что полный baseline на 5000 изображениях уже получен.

## Быстрый старт в Colab

1. Откройте `notebooks/01_baseline_colab.ipynb` в Google Colab.
2. Выберите среду с GPU T4.
3. Выполняйте ячейки по порядку. Ноутбук предложит загрузить архив проекта
   `diffusion-sampling-colab.zip` и подключить Drive для результатов.
4. Сначала выполните pilot, посмотрите изображения, затем один полный батч baseline.
5. По его времени оцените длительность оставшейся генерации и продолжите тот же запуск.
6. Вычислите FID отдельной командой. Она не держит генератор и Inception на GPU одновременно.

Архив собирается командой `python scripts/build_colab_bundle.py`.
Архив содержит исходники, конфигурации, документацию, тесты и ноутбук;
веса, изображения и виртуальное окружение в него не включаются.

## Локальная установка

Запускайте команды из этой папки. Рекомендуется Python 3.10–3.13.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m diffusion_sampling doctor
```

На Mac можно выбрать `--device mps`, если doctor показывает доступный MPS.
Основные сравнительные замеры проводим на одной T4, в одном окружении.
Для начала используем float32 и отключённый TF32. Не включаем CPU fallback для MPS
незаметно: такой запуск смешал бы разные устройства в измерении.

## Первый запуск

```bash
python -m diffusion_sampling prepare-noise
python -m diffusion_sampling run --config configs/pilot.json
```

Pilot — 16 изображений, DDIM 20 шагов, batch size 8. Он проверяет загрузку,
масштабы, сохранение и время. Его изображения не являются итоговым результатом
по качеству. Посмотрите `results/pilot_ddim_20/preview.png`.

Для полноценного baseline на T4:

```bash
python -m diffusion_sampling run --config configs/baseline_ddim_100.json --max-batches 1
python -m diffusion_sampling run --config configs/baseline_ddim_100.json
python -m diffusion_sampling evaluate --run results/baseline_ddim_100 --device cuda --download
```

Первая команда останавливается после одного измеренного батча. Вторая продолжает
с первого отсутствующего батча. Она не генерирует уже сохранённые изображения заново.
В baseline 5000 изображений, DDIM 100 шагов, batch size 64, `eta=0`, clipping включён,
расписание `leading`, коэффициенты beta берутся из checkpoint.

Для маленькой памяти измените batch size **до первого запуска** и выберите новый
`output_dir`. Нельзя менять настройки посередине эксперимента. Команда `evaluate`
использует свой независимый batch size, его можно менять.

## Что сохраняется

| Файл | Содержимое |
|---|---|
| `manifest.json` | Конфигурация, устройство, версии, ревизия и SHA256 весов и шумов |
| `model_contract.json` | Интерфейс U-Net и полная конфигурация DDIM |
| `batches/*.pt` | Сырые float32 результаты до перевода в PNG, время и NFE батча |
| `images/*.png` | RGB 32×32 для FID; без ручного увеличения или фильтров |
| `preview.png` | Увеличенная сетка для визуальной проверки, вне папки FID |
| `summary.json` | Число изображений, время, NFE и готовность численных метрик |
| `fid.json` | FID, размеры выборок, реализация и протокол оценки |

Время включает цикл денойзинга, подготовку scheduler и его шаги. Не включает загрузку
модели, прогрев, перенос начального шума на устройство, перенос результата на CPU,
запись файлов и FID. До и после измерения GPU синхронизируется.
После возобновления время суммируется только по сохранённым батчам. Это сумма времени
генерации, а не календарное время между запуском и завершением.

`nfe_per_image` — число вычислений сети на траекторию одного изображения.
`batched_model_forward_calls` — фактическое число вызовов forward для всех батчей.
Например, 5000 изображений по 100 NFE — 500000 эквивалентных вычислений для отдельных
изображений; число батчевых вызовов зависит от batch size.

При аварии последний недописанный `.tmp` не считается завершённым батчем.
Отсутствующие PNG восстанавливаются из `.pt`. Изменение конфигурации, устройства,
ключевых версий, весов или шумов не позволяет незаметно продолжить старый эксперимент.
Локальная блокировка через POSIX flock в системной временной папке защищает
от двух пишущих процессов одной машины и не требует поддержки блокировок Google Drive.
Разным сессиям Colab нужны разные `output_dir`: блокировка не распределённая.

## Данные и воспроизводимость

```bash
python -m diffusion_sampling prepare-noise --fid-count 5000
python -m diffusion_sampling prepare-data --output data/cifar10
```

Шумы генерируются на CPU: отдельный seed на изображение. Поэтому начальный шум не
зависит от batch size. Сами тензоры и их контрольные суммы сохраняются.
Наборы debug, calibration, validation, evaluation_mse и fid имеют непересекающиеся
диапазоны seeds. Набор FID можно заранее сделать больше; запуск использует его префикс.
Готовый банк автоматически не перезаписывается другим seed или большим размером.

Модель закреплена на commit `267b167`; полная разрешённая ревизия записывается
в manifest. В проекте закреплены Diffusers 0.35.2 и torch-fidelity 0.3.0.
Hugging Face Hub совместим с диапазоном >=0.34,<3, чтобы не понижать зависимость
установленного в Colab Transformers. Версии PyTorch, torchvision и Hub берутся из рабочего окружения
и обязательно записываются. Для точного повторения используйте те же версии и устройство.
Битовая идентичность между CPU, MPS и CUDA не предполагается.

## Как считаем FID

Сравниваем с **всеми 50000 изображениями CIFAR-10 train**. Извлечение признаков:
`torch-fidelity==0.3.0`, `inception-v3-compat`, слой 2048. Generated: исходные RGB PNG
32×32, округление в uint8 после ограничения диапазона. Изменение размера и нормализация
выполняются внутри одной библиотеки и для реальных, и для сгенерированных изображений.

Количество generated в основном baseline — 5000. Это **FID-5k относительно real-50k**,
а не результат FID-50k из статьи. Сравниваем конфигурации только с одинаковым количеством
изображений и одной реализацией метрики. Статистики реальных данных кэшируются;
кэш generated привязан к SHA256 содержимого PNG. Весовой файл Inception также скачивается.

Для завершённого pilot команда оценки разрешена, но результат явно помечается как
маловыборочный. Он не становится полным baseline. Порог предупреждения 2048 —
защита от случайного использования маленького pilot, а не гарантия точности выше порога.
`baseline_metrics_complete` требует purpose=baseline и не менее 5000 изображений.
Визуальную оценку всё равно нужно выполнить и описать отдельно.

FID вычисляется на CUDA или CPU: torch-fidelity 0.3 не использует MPS.
Если датасет заранее подготовлен, флаг `--download` не нужен.
Полностью офлайн запуск также требует заранее сохранить веса Inception.

## Проверки без интернета и GPU

```bash
python -m unittest discover -s tests -v
```

Проверяются совпадение с официальным DDIMPipeline на маленькой тестовой сети,
NFE, независимость шумов от батчей, восстановление после прерывания,
контрольные суммы, отказ при изменении конфигурации и протокол вызова FID.
Также проверяется повторное чтение NumPy-статистик из кэша torch-fidelity на новом
PyTorch: разрешены только необходимые типы массивов, режим безопасной загрузки не отключается.
Тестовые модели и подменённые метрики не используются как результаты исследования.
